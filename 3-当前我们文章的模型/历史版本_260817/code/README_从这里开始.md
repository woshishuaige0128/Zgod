## 图是怎样画出来的

### Fig.6--Fig.9：从响应数据画曲线

每份CSV有40961行时刻，范围为0--40 s，时间步长为1/1024 s。每一层的三列依次是Original、Guyan、Craig--Bampton；绘图时按读者习惯把图例排成Original、Craig--Bampton、Guyan。

每张图有两行：第一行是一层，第二行是三层。每行左边显示0--40 s全时程，中间和右边显示指定局部窗口。El Centro使用10--11 s和21.5--22.5 s；Chirp使用13--14 s和38--38.3 s。

### Fig.10：从论文中的边界点画折线

六份CSV合计386个点。MATLAB按每个文件原有的 `point_order` 顺序连接这些点，并把采样步换算为毫秒：

`时滞毫秒 = (采样步 - 1) × 1000 / 1024`

坐标轴从0开始，但第一批真实边界点位于0.9765625 ms。代码不会为了让线碰到原点而添加不存在的数据点，也不会按横坐标重新排序或改成阶梯线。

## 证据边界

- 五个 `FigXX_.../RUN_THIS_FIGURE.m` 本身仍只负责读取同文件夹数据、检查和出图；它们不是完整计算入口。
- Fig.6--Fig.9的科学数据已由板块18从参数、矩阵、两类缩聚、Simulink固定步长求解和三层物理恢复重新生成。本轮真实复跑后的四份40961×10 CSV与当前四份输入逐字节相同，因此Fig.6--Fig.9属于**计算级复现（现存代码/必要适配路线）**；作者当年保存的历史逐点工作区数组仍未找到。
- Fig.10当前独立绘图文件夹使用从梁禹硕士论文PDF逐点提取并验收的六条边界，属于**论文边界绘图级逐点复现**。
- Fig.10上游已完成六模型链×四候选×31×67网格的49,848点和3,356,432根全计算，并通过MATLAB/Python交叉验证；但R01--R04对论文六条边界均为0/6命中。因此准确结论是“全计算链实现通过，论文边界计算复现未通过”，不能挑一条最像的候选冒充成功。
- MATLAB会重新排版坐标轴、字体和矢量对象，因此新PDF与历史Python/论文PDF不是字节级相同文件；这里通过的是数据、点序、线条身份和版式合同的复现，不是PDF二进制复制。

## 常见问题

- 提示缺少CSV：您只复制了 `.m` 文件。请复制整个 `FigXX_...` 文件夹。
- 无法写入输出：检查该文件夹是否为只读，以及是否有写入权限。
- 图已经出现但找不到文件：查看本图文件夹的 `输出/PDF` 和 `输出/PNG`，不要到MATLAB当前文件夹寻找。
- 字体外观不同：代码优先选择CMU Serif；本机未安装时选择Times New Roman。图中标签和刻度使用MATLAB的LaTeX解释器，因此导出的PDF实际嵌入Computer Modern数学字体，并已确认不含Type 3字体。
- Fig.10曲线没有经过原点：这是输入边界点的真实状态；坐标轴从0开始不等于边界必须包含原点。
